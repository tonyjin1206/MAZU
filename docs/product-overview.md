# Mazu Trade System (MTS) — 产品文档

> 版本 2.8.0 | 最后更新 2026-08-29

> **v2.8.0 销售订单三路分流（三分支）**：销售订单审核后，明细行按业务实际独立走三条路线——**转直采**（采购/贸易型）、**转外发**（委外加工型）、**转生产-自产**（自有生产型）。三者互斥，一条明细行只能走其一，订单本身不再自动生成生产订单。
>
> **v2.6.0 销售退货财务层补强**：销售发票红冲（红字票+红字应收）、退款登记（负数收款核销红字应收）、核销转移（红字应收→同客户正余额）、退货联动（已开票提示红冲 / 已报税打标 refund_declared）、负数申报（已报税退货 → 次月申报冲减）。
>
> **v2.7.0 预警提醒系统**：顶部通知铃铛（未读红点+消息弹层）、业务事件联动提醒（订单审核/转直采/转外发/转生产/通知发货/发货完成/应收生成）、应收/应付账期定时预警（将到期/逾期）、提醒规则配置化。

## 一、系统概述

### 1.1 产品定位

面向中小外贸企业的轻量化 ERP 系统，覆盖采购、销售、生产、库存、财务、退税核心业务闭环。全中文界面，提供开箱即用的业务管理能力。公司**无自有工厂**时走「转直采 / 转外发」，有自有生产时走「转生产-自产」。

### 1.2 技术架构

| 层次 | 技术选型 |
|------|---------|
| 后端框架 | Python FastAPI + SQLAlchemy ORM |
| 数据库 | SQLite（原生部署，无需额外安装数据库服务） |
| 前端框架 | Vue 3 + Vite 构建工具 |
| UI 组件库 | Element Plus |
| 数据可视化 | 原生 CSS 柱状图（管理驾驶舱） |
| 运行方式 | 前后端分离，RESTful API 通信 |

### 1.3 核心设计特性

- **全局UI统一**：所有列表页采用一致的搜索栏 + 边框表格 + 分页布局
- **全链路追溯**：每条业务记录支持穿透查询上游/下游单据
- **状态机驱动**：每笔业务单据有明确的状态流转，每步操作可逆向回退
- **单据编号标准化**：所有业务单据按统一规则自动编号
- **管理驾驶舱**：关键经营指标可视化，支持穿透到明细
- **下游解锁上游**：下游单据存在时上游不可变更/删除，退回下游单据后上游自动解锁

│  前端 Vue 3  │ ←─────────────────────→ │  后端 FastAPI │
│  Vite 开发   │   http://localhost:8788  │  SQLAlchemy   │
│  localhost:  │                         │  ORM          │
│  5173        │                         │               │
└─────────────┘                         └──────┬───────┘
                                               │
                                        ┌──────┴───────┐
                                        │   SQLite      │
                                        │   database    │
                                        │   erp.db      │
                                        └──────────────┘
```

### 2.2 认证机制

系统使用 JWT（JSON Web Token）进行用户认证：
- 登录时 POST `/api/auth/login` 获取 token
- 后续所有业务请求在 Authorization header 中携带 token
- 路由层通过 Depends(get_current_user) 验证用户身份
- 默认管理员账户 admin/admin123，首次启动自动创建

## 三、基础档案管理

| 客户名称（中文） | 必填 |
| 客户名称（英文） | 外贸场景使用 |
| 联系人 |  |
| 联系方式 | 电话/邮箱 |
| 地址 |  |

### 3.2 供应商管理

**功能位置：** 基础档案 → 供应商管理

**功能说明：**
维护供应商信息，供应商分类为原材料供应商、委外供应商等。**委外供应商不做独立表**，供应商类型选「委外」即视为委外商（用于委外工序/委外订单的加工方），无需单独维护。关联采购订单、采购发票、应付账款、委外订单。

**功能位置：** 基础档案 → 原辅材料

**功能说明：**

### 3.4 产品档案

**功能位置：** 基础档案 → 产品档案

**功能说明：**
管理企业的成品/商品信息。产品是销售订单、生产订单的核心对象。支持「是否可外购」标记（`can_purchase`，外购型生产订单确认外购自动打勾）。

**表单字段：** 编码、名称（中文）、名称（英文）、规格、型号、单位、销售单价

### 3.5 BOM 管理

**功能位置：** 基础档案 → BOM管理

**界面布局：** 上下布局（上 = 产品列表，下 = 双页签：组成材料 / 工艺流程），中间 8px 分隔条可拖动调整高度。

**功能说明：**
定义每个产品的物料构成清单（Bill of Materials）和加工工艺路线，是生产模块自动计算物料需求、委外工序拆分、自产派产的依据。

**操作流程：**
1. 上方产品列表点击行选中产品
2. 下方「组成材料」页签：为该产品添加组成物料及用量
3. 下方「工艺流程」页签：按顺序引用参数设置的加工工序，设定加工单价与默认供应商（委外供应商）
4. 支持编辑/删除 BOM 明细行、添加工序、调整工序顺序

### 3.6 工序管理

**功能位置：** 基础档案 → 参数设置 → 加工工序 tab（工序入口已并入参数设置 / BOM 工艺流程）

**功能说明：**
管理生产加工工序，定义每道工序的名称。工序是派产、委外订单拆分和加工费计算的基础。工序**默认自产**（`is_outsource=0`），需委外时在 BOM 工艺流程中指定默认供应商。

**表单字段：** 工序编码、工序名称、状态（启用/停用）

### 3.7 HS编码/退税率

**功能位置：** 基础档案 → HS编码/退税率

**功能说明：**
维护报关用 HS 编码及对应的退税率，用于退税申报模块。

### 3.8 币种/汇率

**功能位置：** 基础档案 → 币种/汇率

**功能说明：**
系统预置常用币种（人民币/美元/欧元/日元/英镑/港币/澳元），支持手工维护汇率与自动获取（腾讯财经，每日 09:00 定时 + 手动按钮）。

## 四、采购管理

### 4.1 业务流程

```
供应商 → 采购订单 → 采购入库 → 采购发票 → 应付账款 → 付款
```

采购订单有一个**上游来源**：销售订单明细行「转直采」后推送到「销售订单转采购」页，在转采购页生成采购订单（按 BOM 展开 / 按供应商拆单）。也支持手工直接新建。

### 4.2 采购订单

**功能位置：** 采购管理 → 采购订单

**功能说明：**
向供应商下达采购指令，记录采购物料、数量、单价、金额等信息。支持成品采购（`product_id` 与 `material_id` 互斥）。

**界面操作：**
- **查询**：按供应商、日期范围、关键词搜索
- **重置**：清空搜索条件
- **新建订单**：打开弹窗，填写供应商、明细行（选择物料后自动带出名称、编码、单位）、数量、单价
- **编辑**：修改订单信息，已审批状态不可修改
- **删除**：删除订单（有下游单据则禁删）
- **审批/反审批**：订单状态流转

### 4.3 采购入库

**功能位置：** 采购管理 → 采购入库（成品从「成品入库」页收货、原料从「原料入库」页收货）

**功能说明：**
对采购到货进行实物入库确认。支持多次入库、超订单量入库。

**操作流程：**
1. 点击"新建入库"打开弹窗
2. 选择采购订单，自动加载该订单的物料明细
3. 选择仓库
4. 填写本次入库数量
5. 确认入库，系统自动生成入库单号、批次号，更新物料档案采购单价

**取消/退回：** 已入库的记录可取消，回退库存数量；未入库的「待入库单」可退回，退回后推送关系解锁。

### 4.4 采购发票

**功能位置：** 采购管理 → 采购发票

**功能说明：**
收到供应商开具的发票后，在系统中记录并关联采购订单。开票后自动生成应付账款 + 进项发票（状态"未匹配"）。

### 4.5 应付账款

**功能位置：** 采购管理 → 应付账款

**功能说明：**
管理企业对供应商的应付款项，支持汇总视图和明细视图。账期预警（将到期/逾期）联动 v2.7.0 预警提醒。

### 4.6 付款单

**功能位置：** 采购管理 → 付款

**功能说明：**
记录向供应商支付款项的操作，关联应付账款进行核销。

## 五、销售管理（三分支核心）

### 5.1 业务流程：销售订单三路分流

销售订单审核（状态 → 已审）后，**不自动生成生产订单**。每条明细行初始为「未生产」，由业务人员按实际选择**三条互斥路线之一**：

```
                                     ┌─→ 【转直采】→ 已通知入库 → 采购管理 → 销售订单转采购
销售订单明细行（未生产） ─ 审核后 ─→ │        → 采购订单 → 采购入库 → 明细行已入库
（三路互斥，只能走其一）                 ├─→ 【转外发】→ 已通知外发 → 委外管理 → 销售订单转委外
                                     │        → 委外订单（分工序/加工商） → 成品入库
                                     └─→ 【转生产-自产】→ 生成生产订单（纯自产）
                                              → 生产管理 → 派产/发料/完工 → 成品入库
```

**三条路线如何选择：**
| 分支 | 业务场景 | 明细行状态 | 下游入口 | 出口 |
|------|---------|-----------|---------|------|
| 转直采 | 贸易型：买 A 卖 A，无生产/委外 | 已通知入库 | 采购管理 → 销售订单转采购 | 采购单 → 入库 → 明细已入库 |
| 转外发 | 委外型：买原料交加工厂做成品 | 已通知外发 | 委外管理 → 销售订单转委外 | 委外订单 → 成品入库 → 明细已入库 |
| 转生产-自产 | 自有生产：车间自产 | 生产中 | 生产管理 → 生产订单 | 生产订单 → 成品入库 → 明细已入库 |

> **三分支互斥**：一条明细行只能走一条路线。转生产后明细行置「生产中」，不能再转直采/转外发；转直采/转外发后同理。如此保证成本归集、库存流转的单一性。

### 5.2 销售订单

**功能位置：** 销售管理 → 销售订单

**功能说明：**
记录客户订单信息，包括产品、数量、单价、金额等。审核后进入三路分流。

**界面操作：**
- **查询/重置**：按客户、日期范围、金额范围搜索
- **新建订单**：选择客户、产品，自动带出销售单价（支持多明细行）
- **编辑/详情**：查看或修改订单（仅待审核可改）
- **审核**：状态 → 已审，明细行初始为「未生产」
- **变更**：修改明细行数量/单价/停售

**明细行操作（审核后）：**
- **转直采**（仅未生产 & 已审核）：推送至「采购管理 → 销售订单转采购」
- **转外发**（仅未生产 & 已审核）：推送至「委外管理 → 销售订单转委外」
- **变更**：修改数量/单价、停售

**明细行生产状态（production_status）：**
| 状态 | 标签 | 说明 |
|------|------|------|
| 未生产 | 未生产 | 初始态，可转直采/转外发 |
| 已通知入库 | 转直采 | 已推送采购链 |
| 已通知外发 | 转外发 | 已推送委外链 |
| 生产中 | 生产中 | 已生成自产生产订单 |
| 已生产 | ✓已生产 | 自产完工 |
| 部分入库 | 部分入库 | 已部分收货 |
| 已入库 | 已入库 | 全部收货完成 |
| 已停售 | 停售 | 明细行作废 |

### 5.3 销售发货

**功能位置：** 销售管理 → 销售发货

**功能说明：**
对销售订单进行实物出库操作，采用批次管理，出库时从指定批次扣减库存。**两步化**：业务员「通知发货」（只填数量不扣库存）→ 库管在「成品出库」页按批次发货（扣库存）→ 业务员判断「发货完成」（必须有出库记录）。

**操作流程：**
1. 选择关联的销售订单
2. 选择出库批次（批次来自库存）
3. 填写发货数量，系统自动计算发货金额
4. 保存后生成发货单号，同时产生销售出库库存流水，扣减对应批次库存

**退货：** 必须已有出库记录才能退；退回原批次、原发货成本，回退订单已发数量。

### 5.4 销售发票

**功能位置：** 销售管理 → 销售发票

**功能说明：**
向客户开具销售发票，关联销售订单。开票后自动生成应收账款。
**支持发票红冲（v2.6.0）**：蓝字开票有上限校验（开票金额 ≤ 订单未开票金额，红字全额冲后额度自动返还）；可为已开票蓝字票做**红冲**，录入一张全额负数红字票（票号手填、金额强制 = 原票全额负数、原票标记"已红冲"），并自动生成等额**红字应收**；红字票禁改禁删、已红冲蓝字票禁删。

### 5.5 应收账款

**功能位置：** 销售管理 → 应收账款

**功能说明：**
管理客户欠款，支持按客户汇总和按明细追踪。
**支持红字应收（v2.6.0）**：发票红冲自动生成红字应收（`is_red`、负数余额），列表**红负绿正**展示；红字应收行可做**退款登记**（生成负数收款单核销红字应收，负余额向 0 靠拢、退超拦截）或**核销转移**（红字应收 → 同客户正余额应收的账务清理，写 `ar_adjustment` 审计，可撤销）。

**汇总视图：** 按客户汇总应收总额、已收金额、余额
**明细视图：** 每笔应收账款的流水记录，含应收日期、金额、收款核销
**账龄计算：** 按应收日期+账期计算到期日，自动计算逾期天数

### 5.6 收款单

**功能位置：** 销售管理 → 收款

**功能说明：**
记录客户付款，关联应收账款进行核销。保存后更新应收账款的已收金额。
**支持退款登记（v2.6.0）**：金额填负数为**退款**，核销红字应收（退超拦截"超过可退余额"）；列表负数金额标红 + "退款"标签。

## 六、生产管理（自产路线）

> **v2.8.0 去委外化**：生产模块 = **纯自产**。委外业务从生产模块剥离、统一归口**转外发**（委外管理模块），生产订单不再含委外商/委外工序/委外发料/委外加工费。

### 6.1 业务流程

```
销售明细转生产 → 生产订单（纯自产）
    → 确认备货方式（自产/外购）→ 展开 BOM（物料需求）
    → 派产（分配工序）→ 发料（按工序+批次）
    → 完工（工序转移）→ 成品入库（材料成本+加工费结转入库）

## 七、委外管理（转外发路线）

> **v2.8.0 归口**：委外业务统一归口**转外发**（销售明细 → 委外管理）。委外订单分工序、每道工序可指定加工商。

### 7.1 业务流程

```
销售明细转外发 → 销售订单转委外
    → 按 BOM 工艺拆分工序卡片（每工序选加工商 + 加工单价 + 委外数量）
    → 认领原料（订单级，按仓库总数量 FIFO 扣批次）
    → 生成委外订单（一工序一供应商，草稿）→ 审核
    → 每张委外订单记加工费应付；仅末道工序生成成品待入库单
    → 成品入库收货（成品数量 = 产品数量）
```

### 7.2 销售订单转委外

**功能位置：** 委外管理 → 销售订单转委外

**功能说明：**
从左侧到右侧的**工序层级关系面**：产品 → 按 seq 依次展开各工序节点（节点间连线），一眼看清"这个产品有几道工序、顺序如何"。每个工序节点配置：加工商（默认工序默认供应商）、加工单价、委外数量、供料方式（己方提供/包工包料）、认领原料按钮。底部"生成委外订单"。

### 7.3 委外订单

**功能位置：** 委外管理 → 委外订单

**功能说明：**
每道工序生成一张委外订单（一个供应商一张）。审核后：生成加工费应付账款；仅**末道工序**生成成品待入库单（非末道工序只记加工成本）。已审核可取消审核。

**供料方式（`supply_type`）**：
- 己方提供：需认领原料（认领量 ≥ 委外数量 × BOM用量 × (1+损耗%)），扣库存
- 包工包料：由加工厂提供，不认领、不出库

**删除委外订单：** 材料自动退回原批次（单据链闭环）。

### 7.4 加工费发票

**功能位置：** 委外管理 → 加工费发票

**功能说明：**
记录委外加工产生的加工费发票，关联委外订单/生产订单。金额完全由工序完工/委外数据计算，不接受用户输入。

## 十二、成本流转机制

### 12.1 生产成本核算（自产）

生产模块的成本核算贯穿整个生产到销售的全过程：
```
生产订单
  ├─ 物料成本 ← 发料时的材料数量 × 物料采购单价
  └─ 加工费 ← 工序完工后记录的加工费用
       ↓
成品入库计算：
  单位成本 = (本次转出材料成本 + 本次转出加工费) / 入库数量
  写入库存余额的 unit_cost
       ↓
销售发货出库：
  出库成本 = 出库数量 × 库存 unit_cost
       ↓
销售毛利 = 发货收入 - 出库成本
```

### 12.2 委外加工成本（转外发）

委外型走「采购线买原料 + 委外线加工费」，成本汇集到成品入库：
- 原料成本 = 认领原料数量 × 物料采购单价（己方提供）
- 加工费 = 各工序委外订单加工费
- 成品入库成本 = 原料成本 + 加工费，单位成本 = 成本 / 成品数量

AI 助手通过自然语言对话完成 ERP 操作，无需手动操作菜单。入口为页面右下角全局悬浮球。

**核心工具：**
| 工具 | 功能 |
|------|------|
| query_entities | 查询客户/供应商/物料/产品/应收/应付/发票清单 |
| query_inventory | 查询当前库存 |
| query_pending_approvals | 列待审核单据 |
| approve_order | 审核采购/销售订单（**销售审核不再自动生成生产订单**，v2.8.0） |
| unapprove_order | 反审核采购订单 |
| query_manual | 查操作手册章节 |
| create_order | 创建采购/销售订单（多明细行） |
| create_collection | 创建收款单 + 自动核销应收账款 |
| create_payment | 创建付款单 + 自动核销应付账款 |
| create_purchase_invoice | 录入采购发票 |
| create_sales_invoice | 录入销售发票 |
| issue_materials | 生产领料/发料（纯自产，v2.8.0 去委外语义） |
| production_receipt | 生产完工入库 |

**v2.8.0 三分支引导**：销售订单审核后 AI 会提示明细行处于「未生产」，需为每行选择三条独立路线之一（转直采 / 转外发 / 转生产-自产），AI 能区分转外发=委外、转生产=自产，不会替用户假设路线。

### 16.2 工作流程

所有创建类操作采用「三步确认」流程：
1. **确认意图** — AI 问清用户要做什么
2. **收集字段** — 一次只问一个，用户说完再问下一个
3. **核对执行** — 列出全部字段让用户确认，确认后调用工具执行

查询类直接返回数据，不编造。所有操作按菜单权限控制，全程留痕。

## 十七、权限体系（RBAC）

> v1.2.0 引入 RBAC 用户权限体系，v2.3.0 菜单级权限前端落地，v2.8.0 三分支写端点按业务域授权。

基于角色的访问控制（Role-Based Access Control）。角色按岗位配置（销售经理/采购经理/生产经理/财务经理/库管员/只读），每个角色勾选可见菜单。

**权限模型：**
- 菜单级权限：侧边栏可见性 + 路由守卫校验
- 按钮级权限：审核/删除/作废等
- 管理员（admin）恒全权限

**v2.8.0 三分支权限隔离（写端点按业务域授权）：**
| 分支 | 接口 | 授权域 |
|------|------|--------|
| 转直采 | `stock-in` | `menu:sales:orders`（销售本域） |
| 转外发 | `outsource` | `menu:sales:orders` + `menu:outsource:*`（销售本域+委外域） |
| 转生产 | `re-produce` | `menu:sales:orders` + `menu:production:orders`（销售本域+生产自产域） |

库管员/只读等低权限角色访问非授权域 → 403。

## 十八、预警提醒系统（v2.7.0）

> 按角色自动推送业务提醒与账期预警，站内消息中心（顶部铃铛）承接，实时可见、可跳转。

### 18.1 业务联动提醒（自动触发）

| 触发 | 提醒谁 | 干什么 |
|------|-------|-------|
| 销售订单**审核通过** | 销售经理 | 对明细行做转直采/转外发/转生产，并安排发货 |
| 明细行**转直采** | 采购经理 | 到「销售订单转采购」下单 |
| 明细行**转外发** | 采购经理 | 到「销售订单转委外」安排工序+买原料 |
| 明细行**转生产**（v2.8.0） | 生产经理 | 到「生产管理」安排排产与发料 |
| **通知发货**（待出库） | 库管员 | 到「成品出库」按批次出库 |
| 明细行**发货完成** | 销售经理 | 安排开票 |
| **应收生成** | 财务+销售 | 财务入账、销售跟进催收 |

### 18.2 账期预警（每日 09:00 自动扫描）

应收/应付将到期与逾期提醒（红字应收不参与）。规则可在「系统管理 → 通知管理」配置启用/停用、标题/正文模板、接收角色、提前天数/去重窗口。
