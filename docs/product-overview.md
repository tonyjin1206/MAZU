# Mazu Trade System (MTS) — 产品文档

> 版本 2.1.0 | 最后更新 2026-07-30

---

## 一、系统概述

### 1.1 产品定位

面向中小外贸企业的轻量化 ERP 系统，覆盖采购、销售、生产、库存、财务核心业务闭环。全中文界面，提供开箱即用的业务管理能力。

### 1.2 技术架构

| 层次 | 技术选型 |
|------|---------|
| 后端框架 | Python FastAPI + SQLAlchemy ORM |
| 数据库 | SQLite（原生部署，无需额外安装数据库服务） |
| 前端框架 | Vue 3 + Vite 构建工具 |
| UI 组件库 | Element Plus |
| 数据可视化 | 原生 CSS 柱状图（管理驾驶舱） |
| 运行方式 | 前后端分离，RESTful API 通信 |

### 1.3 核心设计特性

- **全局UI统一**：所有列表页采用一致的搜索栏 + 边框表格 + 分页布局
- **全链路追溯**：每条业务记录支持穿透查询上游/下游单据
- **状态机驱动**：每笔业务单据有明确的状态流转，每步操作可逆向回退
- **单据编号标准化**：所有业务单据按统一规则自动编号
- **管理驾驶舱**：关键经营指标可视化，支持穿透到明细

### 2.3 数据流向

```
用户交互 → Vue 页面 → axios API 请求 → FastAPI 路由
    → SQLAlchemy ORM 查询/写入 → SQLite 数据库
    → 响应数据序列化 → 返回前端 → 渲染页面
```

**API 请求流程：**
```
前端组件 → foundationApi.materials.list(params)
    → request.get('/foundation/materials', { params })
    → FastAPI GET /api/foundation/materials
    → SQLAlchemy 查询 fd_material 表
    → Pydantic MaterialOut 序列化
    → JSON 响应返回前端
    → Vue 响应式更新表格数据
```

### 2.4 认证机制

系统使用 JWT（JSON Web Token）进行用户认证：
- 登录时 POST `/api/auth/login` 获取 token
- 后续所有业务请求在 Authorization header 中携带 token
- 路由层通过 Depends(get_current_user) 验证用户身份
- 默认管理员账户 admin/admin123，首次启动自动创建

| 模块 | 子功能 |
|------|--------|
| 基础档案 | 客户 / 供应商 / 物料 / 产品 / BOM / 工序 / HS编码 |
| 采购管理 | 采购订单 → 采购入库 → 采购发票 → 应付账款 → 付款 |
| 销售管理 | 销售订单 → 销售发货 → 销售发票 → 应收账款 → 收款 |
| 生产管理 | 生产订单 → 派产 → 发料 → 完工 → 成品入库 / 委外工单 / 加工费发票 |
| 库存管理 | 库存余额 / 库存流水 / 批次追溯 |

## 三、基础档案管理

基础档案是系统运行的基础数据，其他所有业务模块都依赖于基础档案中的数据。

### 3.1 客户管理

**功能位置：** 基础档案 → 客户管理

**功能说明：**
维护企业与客户的基本信息，客户数据关联销售订单、销售发票、应收账款。

**表单字段：**
| 字段 | 说明 |
|------|------|
| 客户编码 | 唯一标识，自动或手动录入 |
| 客户名称（中文） | 必填 |
| 客户名称（英文） | 外贸场景使用 |
| 联系人 |  |
| 联系方式 | 电话/邮箱 |
| 地址 |  |
| 信用额度 | 可选设置 |

**操作按钮：**
| 按钮 | 功能 |
|------|------|
| 查询 | 按编码/名称/联系人关键词搜索客户列表 |
| 重置 | 清空搜索条件并刷新列表 |
| 新增客户 | 打开新建客户表单弹窗 |
| 编辑 | 点击行编辑按钮修改客户信息 |
| 删除 | 确认后删除（如有下游单据则禁止删除） |

### 3.2 供应商管理

**功能位置：** 基础档案 → 供应商管理

**功能说明：**
维护供应商信息，供应商分类为原料供应商、辅料供应商、委外供应商，关联采购订单、采购发票、应付账款。

**表单字段：** 编码、名称、联系人、联系方式、供应商类型（原料/辅料/委外）、地址

### 3.3 物料档案

**功能位置：** 基础档案 → 原辅材料

**功能说明：**
管理生产用原材料和辅料。物料是采购入库和生产发料的最小管理单元。

**表单字段：**
| 字段 | 说明 |
|------|------|
| 物料编码 | 唯一标识 |
| 物料名称 |  |
| 规格 | 物料的规格参数 |
| 型号 | 物料的型号 |
| 单位 | 如个/包/米/千克等，采购订单和入库时自动带出 |
| 分类 | 原材料/辅料/包装材料等 |
| 采购单价 | 最近一次采购入库自动回写 |

**功能操作：**
- 新建物料：填写编码、名称、规格、型号、单位等信息
- 编辑物料：修改除编码外的所有字段
- 搜索过滤：按编码/名称/分类关键词搜索

### 3.4 产品档案

**功能位置：** 基础档案 → 产品档案

**功能说明：**
管理企业的成品/商品信息。产品是销售订单、生产订单的核心对象。

**表单字段：** 编码、名称（中文）、名称（英文）、规格、型号、单位、销售单价

### 3.5 BOM 管理

**功能位置：** 基础档案 → BOM管理

**界面布局：** 左 40% 产品列表 + 右 60% BOM明细

**功能说明：**
定义每个产品的物料构成清单（Bill of Materials），是生产模块自动计算物料需求的依据。

**操作流程：**
1. 左侧产品列表点击行选中产品
2. 右侧显示该产品的 BOM 明细
3. 点击"新增材料"为该产品添加组成物料及用量
4. 支持编辑/删除 BOM 明细行

### 3.6 工序管理

**功能位置：** 基础档案 → 工序管理

**功能说明：**
管理生产加工工序，定义每道工序的名称和加工单价。工序是派产和加工费计算的基础。

**表单字段：** 工序编码、工序名称、单价

### 3.7 HS编码/退税率

**功能位置：** 基础档案 → HS编码/退税率

**功能说明：**
维护报关用 HS 编码及对应的退税率，用于退税申报模块。

## 四、采购管理

### 4.1 业务流程

```
供应商 → 采购订单 → 采购入库 → 采购发票 → 应付账款 → 付款
```

### 4.2 采购订单

**功能位置：** 采购管理 → 采购订单

**功能说明：**
向供应商下达采购指令，记录采购物料、数量、单价、金额等信息。订单状态管理：待审批 → 已审批 → 部分入库 → 已入库。

**界面操作：**
- **查询**：按供应商、日期范围、关键词搜索
- **重置**：清空搜索条件
- **新建订单**：打开弹窗，填写供应商、明细行（选择物料后自动带出名称、编码、单位）、数量、单价
- **编辑**：修改订单信息，已审批状态不可修改
- **删除**：删除订单
- **审批/反审批**：订单状态流转

**新建弹窗表单字段：**
| 字段 | 说明 |
|------|------|
| 供应商 | 从供应商档案选择 |
| 订单日期 | 默认当天 |
| 交货日期 |  |
| 物料编码 | 下拉选择物料，选后自动填充名称/编码/单位 |
| 物料名称 | 自动带出 |
| 物料编码 | 自动带出 |
| 单位 | 自动从物料档案带出 |
| 数量 | 手动输入 |
| 单价 | 手动输入 |
| 含税金额 | 自动计算 |
| 总金额 | 所有明细行含税金额合计 |
| 总税额 | 自动计算 |
| 不含税总金额 | 自动计算 |

### 4.3 采购入库

**功能位置：** 采购管理 → 采购入库

**功能说明：**
对采购到货进行实物入库确认。支持多次入库、超订单量入库。

**操作流程：**
1. 点击"新建入库"打开弹窗
2. 选择采购订单，自动加载该订单的物料明细
3. 选择仓库
4. 填写本次入库数量
5. 确认入库，系统自动生成入库单号、批次号，更新物料档案采购单价

**界面字段：**
| 字段 | 说明 |
|------|------|
| 物料名称 | 从采购订单带出 |
| 编码 | 自动带出 |
| 单位 | 从物料档案自动带出 |
| 订单数量 | 采购订单数量，只读 |
| 已入库 | 已入库数量，只读 |
| 本次入库 | 手动输入，不能超过剩余可入库数量 |
| 入库批次 | 保存后自动生成 |

**取消入库：** 已入库的记录可取消，取消后回退库存数量。

### 4.4 采购发票

**功能位置：** 采购管理 → 采购发票

**功能说明：**
收到供应商开具的发票后，在系统中记录并关联采购订单。

**操作流程：**
1. 点击"新建"打开弹窗
2. 选择供应商
3. 选择采购订单，自动显示未开票金额
4. 填写含税金额、税率，自动计算税额和不含税金额
5. 保存后开票金额从订单未开票金额中扣减

**特殊说明：** 创建发票后，下次再次新建时会自动刷新订单的未开票金额。

### 4.5 应付账款

**功能位置：** 采购管理 → 应付账款

**功能说明：**
管理企业对供应商的应付款项，支持汇总视图和明细视图。

**汇总页签：** 按供应商汇总应付总额、已付金额、余额
**明细页签：** 以应付单为行（一张应付单一行），付款单号多单 tag 拼接、付款金额汇总，余额 = 应付金额 − 付款金额；行级付款核销流水（逐笔 + 备注）在「详情」弹窗查看
**穿透查询：** 点击汇总行自动切换到明细页签并过滤该供应商

### 4.6 付款单

**功能位置：** 采购管理 → 付款

**功能说明：**
记录向供应商支付款项的操作，关联应付账款进行核销。

**操作流程：**
1. 点击"新建"选择供应商
2. 选择要核销的应付账款记录
3. 输入付款金额
4. 保存后更新应付账款的已付金额和余额

## 五、销售管理

### 5.1 业务流程

```
客户 → 销售订单 → 生产/备货 → 销售发货 → 销售发票 → 应收账款 → 收款
```

### 5.2 销售订单

**功能位置：** 销售管理 → 销售订单

**功能说明：**
记录客户订单信息，包括产品、数量、单价、金额等。

**界面操作：**
- **查询/重置**：按客户、日期范围、金额范围搜索
- **新建订单**：选择客户、产品，自动带出销售单价
- **编辑/详情**：查看或修改订单
- **确认/取消确认**：订单状态流转

**弹窗字段：** 客户、产品编码（可选后自动带名称/规格/型号/单位）、数量、单价、含税金额、税率、税额、不含税金额

### 5.3 销售发货

**功能位置：** 销售管理 → 销售发货

**功能说明：**
对销售订单进行实物出库操作，采用批次管理，出库时从指定批次扣减库存。

**操作流程：**
1. 选择关联的销售订单
2. 选择出库批次（批次来自库存）
3. 填写发货数量，系统自动计算发货金额
4. 保存后生成发货单号，同时产生销售出库库存流水，扣减对应批次库存

**销售退货（客户退回）：**
发货单支持退货，可多次部分退。退货自动完成：退回原批次库存（沿用原发货成本）、生成红字退货单（负向发货单）、回退订单已发数量与状态、驾驶舱毛利自动冲减。
- **未开票**：直接退货即可
- **已开票**：退货弹窗提示订单发票状态，涉及已开票部分需到「销售发票」全额红冲
- **已报税**：退货单自动标记，退税数据冻结不动，次月申报表做负数申报冲减（发票红冲不受影响）

### 5.4 销售发票

**功能位置：** 销售管理 → 销售发票

**功能说明：**
向客户开具销售发票，关联销售订单。开票后自动生成应收账款。

**操作流程：**
1. 选择客户
2. 选择销售订单，自动显示未开票金额（开票金额不可超过未开票金额）
3. 输入含税金额、税率，自动计算
4. 保存后开票金额扣减订单未开票金额

**发票红冲（全额红冲）：**
- 发票错误/退货需冲销时点「红冲」，弹窗手工录入红字发票号（客户开票系统生成）、金额自动固定为原发票全额负数不可修改
- 红冲后：原发票标记「已红冲」、自动生成等额红字应收、开票额度自动返还（可补开新票）
- 红字发票不可修改/删除，发票列表显示「红冲发票号码」列追溯原票，红字金额标红
- 发票删除已移除（财务不可逆，一律走红冲），已收款发票删除会被拦截

### 5.5 应收账款

**功能位置：** 销售管理 → 应收账款

**功能说明：**
管理客户欠款，支持按客户汇总和按明细追踪。

**汇总视图：** 按客户汇总应收总额、已收金额、余额（负数=应退客户，红色显示；正数绿色）
**明细视图：** 以应收单为行（一张应收单一行），核销/收款/转移全部汇总金额展示——收款单号、转移来源单据号多单 tag 拼接，余额 = 应收金额 − 核销转移金额 − 收款金额；行级流水（收款/退款核销、核销转移逐笔 + 备注）在「详情」弹窗查看
**账龄计算：** 按应收日期+30天计算到期日，自动计算逾期天数

**红字应收（应退客户）：**
发票红冲自动生成等额红字应收（负数）。红字应收行提供两个操作：
- **退款**：登记负数收款单核销红字应收（应退余额向 0 靠拢），实际退款线下办理
- **核销转移**：把红字应收余额转移到同客户其他正余额应收（货款抵扣），钱不动纯账务合并；明细行显示转移金额与来源单据号，可撤销（多笔转移时选择撤销哪笔）——源应收负余额恢复、目标已收回退

### 5.6 收款单

**功能位置：** 销售管理 → 收款

**功能说明：**
记录客户付款，关联应收账款进行核销。保存后更新应收账款的已收金额。

**退款（负数收款单）：**
金额为负的收款单即退款单（单据号带「退款」标签、金额标红），核销红字应收。退款单删除自动回滚应收。

## 八、退税申报

**功能位置：** 退税管理 → 退税申报

**功能说明：**
管理出口退税申报流程，按申报期生成申报批次，关联对应的销售发票。

**报关单（商品行）：** 一票报关单可报多个商品行（多明细订单每个商品一个 HS 编码，自动从产品档案带出可改）；商品行金额合计=报关金额；报关单号全局唯一、同发货单/订单不可重复报关、已申报退税禁删。

**操作流程：**
1. 新建申报期：填写申报年度、月份
2. 关联发票：选择该期要申报的销售发票
3. 提交申报：标记为申报中
4. 状态跟踪：申报中 → 审核中 → 已退税 / 已驳回

**负数申报（已报税退货冲减）：**
已报税发货单发生退货后（退货单自动标记"已报税"），需在次月申报表做负数申报冲减出口额：
1. 新建次月申报表 → 明细编辑页点「添加退货冲减（负数申报）」
2. 选择已报税退货单 → 自动生成负数明细行（计税金额/可退税额为负）
3. 申报表出口FOB金额自动重算（原值-退货额）；负退税结转下期，不产生退税

**申报明细双端匹配（退税怎么对上发票和报关单）：**
1. 明细编辑页点「＋ 添加申报行（发票+报关单）」→ 先选**进项发票**（采购端，已选/已匹配的自动置灰）→ 再选**报关单商品行**（出口端，仅已放行/已结关报关单可选，已选自动置灰）
2. 系统自动带出：商品/HS编码/数量/出口FOB金额/退税率，可退税额 = FOB × 退税率
3. 申报表出口FOB金额自动汇总明细行并重算免抵退；明细表「报关单号」列展示每行对应的出口报关单

**查询条件：** 关键词、申报状态、日期范围

## 十一、成本流转机制

### 11.1 生产成本核算

生产模块的成本核算贯穿整个生产到销售的全过程：

```
生产订单
  ├─ 物料成本 ← 发料时的材料数量 × 物料采购单价
  └─ 加工费 ← 工序完工后记录的加工费用
       ↓
成品入库计算：
  单位成本 = (本次转出材料成本 + 本次转出加工费) / 入库数量
  写入库存余额的 unit_cost
       ↓
销售发货出库：
  出库成本 = 出库数量 × 库存 unit_cost
  写入库存流水的 total_amount
       ↓
销售毛利 = 发货收入 - 出库成本
```

### 11.2 成本数据来源

| 成本要素 | 来源 | 录入方式 |
|---------|------|---------|
| 物料成本 | BOM物料用量 × 物料采购单价 | 物料发料时自动计算，入库时确认转出 |
| 加工费 | 工序加工单价或委外报价 | 工序完工时记录，入库时确认转出 |
| 成品入库成本 | 物料成本 + 加工费 | 入库弹窗手动录入，系统自动计算单位成本 |
| 出库成本 | 入库时的加权平均 unit_cost | 出库时自动从库存读取 |
| 销售毛利 | 发货收入 - 出库成本 | 驾驶舱自动计算 |

### 14.4 数据存储与测试库隔离

系统数据存放在 SQLite 单文件数据库中，通过 `ERP_DATA_DIR` 环境变量决定数据目录
（`backend/app/config.py`）。开发/生产与测试使用**完全隔离**的数据库，互不干扰。

| | 开发/生产库 | 测试库（pytest） | 测试库（E2E） |
|---|---|---|---|
| 位置 | `backend/data/erp.db`（默认） | `ERP_DATA_DIR` 指向的临时目录 | `ERP_DATA_DIR` 指向的临时目录 |
| 端口 | 后端 8788 + 前端 5173 | 无端口（TestClient 进程内） | 后端 8789 + 前端 5174 |
| 数据 | 手工录入 + seed 脚本的真实业务数据 | `test_data.py` 构建的测试档案 | 同 pytest，用完即删 |
| 生命周期 | 持久保存 | 每次 pytest 新建，跑完清空 | 测试结束 `shutil.rmtree` 删除 |
| 被谁访问 | 浏览器前端、迁移脚本、手工 | 仅 pytest 进程 | 仅 E2E 进程 |

**隔离机制**：`backend/tests/conftest.py` 在导入应用前设置
`ERP_DATA_DIR=<临时目录>`，使所有测试（含 `setup_db` 清空重建）只作用于测试库；
浏览器/前端始终连接开发库。因此跑测试不会影响开发数据——包括 AI 配置
（`sys_bot_config`）、手工录入的档案、业务单据。

> 历史上曾因测试未隔离而清空开发库（AI 配置丢失），该规范为强制要求，
> 详见 README「测试数据规范」。

## 十五、AI 智能助手

> v2.0.0 新增 — 基于 Function Calling Agent 的自然语言对话式操作
>
> v2.1.0 增强 — 创建订单支持多明细行一次创建，可一句话完成含多种物料/产品的订单

### 15.1 功能概述

AI 助手通过自然语言对话完成 ERP 操作，无需手动操作菜单。支持 8 个工具：

| 工具 | 功能 |
|------|------|
| query_entities | 查询客户/供应商/物料/产品/应收/应付/发票清单（支持模糊搜索 + 全部列出）|
| create_order | 创建采购订单/销售订单（支持多种物料/产品一次创建，v2.1.0 新增多明细行支持） |
| create_collection | 创建收款单 + 自动核销应收账款 |
| create_payment | 创建付款单 + 自动核销应付账款 |
| create_purchase_invoice | 录入采购发票（关联采购单）|
| create_sales_invoice | 录入销售发票（关联销售单）|
| issue_materials | 生产领料/发料 |
| production_receipt | 生产完工入库 |

### 15.2 工作流程

所有创建类操作采用「三步确认」流程：

1. **确认意图** — AI 问清用户要做什么（下单/收款/付款/发票/委外/发料/入库）
2. **收集字段** — 一次只问一个，用户说完再问下一个
3. **核对执行** — 列出全部字段让用户确认，确认后调用工具执行

查询类直接返回数据，不编造。

### 15.3 技术实现

- 引擎：Function Calling Agent（OpenAI / DeepSeek 兼容）
- 提示词：支持用户在系统管理页自定义
- 加密：API Key 使用 Fernet 加密存储，不会泄露到日志或网络
