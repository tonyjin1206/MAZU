# 销售退货 · 发票红冲 · 负数申报 方案（v1.0）

> 状态：方案确认稿（2026-08-03，分支 app-optimization）
> 范围：销售退货全链路补强 —— 发票全额红冲 + 应收联动 + 退款（负数收款）+ 核销转移 + 已报税退货负数申报
> 原则：先方案后代码；已确认决策以本文件为准；未决项见「开放问题」

## 一、业务场景矩阵（退货发生时下游走到哪一步）

退货 = 发货后的退货，**退货单只挂订单，不挂发票**（避免"必须开票才能退货"）。

| 场景 | 红字发货单<br>(库存回库/订单回退/毛利冲减) | 发票 | 应收 | 收款 | 退税 |
|---|---|---|---|---|---|
| (1) 已发货未开票 | ✅ | — | — | — | — |
| (2) 已发货已开票 | ✅ | **全额红冲**（手动）+ **补开新票**（手动） | 红字应收自动联动 | — | — |
| (3) +已收款 | ✅ | 同上 | 同上 | **负数收款单（退款）核销红字应收** | — |
| (4) +已报税 | ✅ | 同上（**发票可红冲，只冻结退税数据**） | 同上 | 同上 | **不动，次月负数申报** |

## 二、核心决策（已确认）

1. **发票只做红冲，不作废**（数电票时代无作废）。红冲 = **全额红冲**，不可部分、不可手工干预金额。
2. **红冲全部，补开正常发货部分**：红字发票永远 = 原发票全额负数；退货未涉及的部分由操作员手工补开一张正确新票。
3. **应收红冲跟随发票红冲**（红字发票 → 自动生成等额红字应收），不跟退货金额走 —— 保证红字发票与红字应收永远等额。
4. **已收款不自动退款**，退款走**负数收款单**（复用收款单，金额为负=退款）。
5. **三表模型**：应收表 + 收款表 + 核销关系表（现有结构，不动）。退款 = 负数收款单（核销关系照常挂）；核销转移 = 独立 `ar_adjustment` 表（应收间余额平移，不塞核销关系表）。
6. **已报税退货**：发票可红冲（税局发票系统与退税申报独立），**退税数据冻结不动**，次月做**负数申报**（本次一并开发）。
7. **红字语义**：应收/发票列表，负数（红字/应退）**红色**，正数**绿色**。
8. **所有发票列表加「红冲发票号码」列**：红字发票显示被它红冲的原发票号；正常发票为空。

## 三、数据模型变更

### so_invoice（销售发票）
| 字段 | 类型 | 说明 |
|---|---|---|
| `is_red` | Integer, default 0 | 是否红字发票 |
| `red_of_invoice_id` | FK so_invoice.id, nullable | 红字发票 → 被红冲的原发票 |
| status | 现有 | 增加取值 `已红冲`（原发票红冲后标记）；保留已开票/已作废历史值，不再有作废入口 |

### ar_account（应收）
| 字段 | 类型 | 说明 |
|---|---|---|
| `is_red` | Integer, default 0 | 是否红字应收 |
| `red_of_ar_id` | FK ar_account.id, nullable | 红字应收 → 原应收（应收列表直接可追溯） |

### ar_collection_alloc（核销关系表）
**保持现状，不改**。语义：纯「收款单 ↔ 应收单」对应关系（collection_id ↔ ar_account_id + allocated_amount）。
- 收款核销：正数收款单 → 核销正应收（现状）
- 退款核销：**负数收款单** → 核销红字应收（天然兼容，退款单也是收款单，金额为负）
- 核销转移**不落此表**（无收款单参与，见 ar_adjustment）

### ar_collection（收款单）
金额为负 = 退款（退款单），单号规则沿用 CR-YYYYMMDD-NNN。核销记录照常挂 ar_collection_alloc。

### ar_adjustment（新增：应收间余额调整）
| 字段 | 说明 |
|---|---|
| `source_ar_id` | 源应收（红字应收，负余额） |
| `target_ar_id` | 目标应收（同客户，正余额） |
| `amount` | 转移金额 |
| operator / remark / created_at | 审计 |

转移动作：source.balance += amount（负余额向 0 靠拢）；target.balance -= amount；两端状态重算。

### so_delivery（发货单）
| 字段 | 类型 | 说明 |
|---|---|---|
| `refund_declared` | Integer, default 0 | 退货单标记：关联报关单已报税（场景4），负数申报取数依据 |

## 四、后端端点设计

### 1. 红字发票 = 手工录入（复用开票端点加红字参数）
```
发票号规则：与蓝字发票一致（操作员手填，从客户开票系统抄录，系统不编码）
入口：前端发票列表 正常票行 → 「红冲」按钮 → 弹窗：
  - 显示原票信息（票号/金额，只读）
  - 红字票号：手填（开票系统生成的红字票号）
  - 金额：自动带出 = 原票全额负数（amount/tax_amount/total_amount 全部取负，只读不可改）
  - 确认后调用开票端点（POST /invoices），带 red_of_invoice_id=原票id

后端校验（red_of_invoice_id 存在时）：
  - 原票存在、is_red=0、status != 已红冲（红字票不能再红冲）
  - 红字票金额必须 = 原票全额负数（不允许手工干预金额）
  - 红字发票不适用"≤ 未开票金额"校验（负数计入 SUM，额度自动返还）
动作：
  - 创建红字发票：is_red=1，red_of_invoice_id=原票id，金额为原票全额负
  - 原发票 status = "已红冲"
  - 自动生成红字应收：金额 = 红字票全额负数，is_red=1，
    red_of_ar_id = 原发票对应的应收 id（source_type=sales_invoice, source_id=原票id）
  - 原应收不动（收款核销记录挂它身上，保留审计）
返回：红字发票号 + 红字应收号
```
账务自洽性（已验证）：
- 开票 10000 收 4000，全额红冲 → 红字应收 -10000，合并应收 = 6000 + (-10000) = -4000 = 应退 4000 ✓
- 补开新票 6000 → 合并 = 6000 + (-10000) + 6000 = 2000 ✓（客户欠 2000 = 原应收 6000 - 退货 4000）

### 2. 开票校验补强 `POST /api/sales/invoices`
```
新增校验：本次开票 total_amount ≤ max(0, 订单未开票金额)
未开票金额 = 订单 total_amount - SUM(所有发票 total_amount)（含红字，口径不变）
红字发票不走此端点（走 red-reverse），不占用此校验
```

### 3. 退货端点改造 `POST /api/sales/deliveries/{id}/return`
```
保留：库存回库（原批次原成本）/ 红字发货单 / 回库流水 / delivered_qty+订单状态回退 / 毛利冲减
新增：
  - 检查关联报关单 refund_status：
    - 待申报     → 允许退货，提示"该单已列入申报表，请更新申报明细"
    - 已申报/审核中/已退税 → 允许退货（库存事实必须记），红字发货单打标 refund_declared=1，
      提示"退税已申报：发票可红冲，退税数据不动，次月负数申报自动带出"
  - 返回订单发票状态提示：该订单已开票金额 / 已红冲金额 / 本次退货金额，
    提示操作员对已开票部分做全额红冲（避免坑2：全退后误补开）
```

### 4. 负数收款单（退款）— 改造 `POST /api/sales/collections`
```
允许 amount 为负 = 退款登记；核销记录照常写入 ar_collection_alloc（负数收款单挂红字应收）
核销目标：红字应收
校验：退款核销金额 ≤ 该红字应收负余额绝对值；核销后红字应收 balance ≤ 0（不能退超）
账务：红字应收 balance 向 0 靠拢（-10000 退 4000 → -6000），合并口径归零 ✓
注意：红字应收不能套用正数公式 balance = amount - collected 直算，
      退款核销方向为 balance += 退款额（collected 语义保持审计）
```

### 5. 核销转移 `POST /api/sales/ar/transfer`
```
入参：source_ar_id（红字应收，负余额）、target_ar_id（同客户正余额应收）、金额
校验：
  - source 与 target 必须同客户（跨客户 = 三角债，禁止）
  - 金额 ≤ source 负余额绝对值 且 ≤ target 余额
  - source 必须是红字应收（is_red=1）；target 必须是正余额
动作：写入 ar_adjustment（转移记录）
      source.balance += 金额；target.balance -= 金额；两端状态重算
不写 ar_collection_alloc（核销关系表只承载收款↔应收）
```

### 6. 负数申报（场景4，本次开发）
```
数据源：refund_declared=1 的退货单 → 关联报关单
新建申报表（create_declaration）时：自动带出"已报税且已退货"的报关单 → 生成负数明细行
计算规则：
  - 申报表 export_amount_fob = 正数行 + 负数行汇总
  - 明细/标准格式行金额支持负数
  - 汇总后 actual_refund ≤ 0 → 不退税、结转下期（负退税 = 冲回已退税额，不产生现金流）
```
