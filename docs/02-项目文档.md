## 一、技术架构

### 1.1 总体架构

前后端分离的单体应用：

```
┌────────────────────────────┐        ┌──────────────────────────────┐
│  前端 Vue 3 + Vite + EP    │  /api  │  后端 FastAPI (uvicorn:8788) │
│  开发 5173 / 构建静态托管   │ ─────▶ │  routers → services/utils     │
└────────────────────────────┘  代理   │        │ SQLAlchemy 2.0       │
                                       │        ▼                      │
                                       │  SQLite backend/data/erp.db   │
                                       │  (WAL + 外键 + busy_timeout)  │
                                       └──────────────────────────────┘
```

- **后端**：Python 3.10+，FastAPI 0.111 + SQLAlchemy 2.0.31 + Pydantic v2（pydantic-settings 管理配置），uvicorn 承载，端口 **8788**。
- **前端**：Vue 3 + Vite 8 + Element Plus 2.14 + vue-router 4 + axios + marked（AI Markdown 渲染）+ sortablejs（列设置拖拽）。开发端口 **5173**，`/api` 代理到 8788；生产模式由后端直接托管 `frontend_dist` 静态文件（SPA fallback）。
- **数据库**：单个 SQLite 文件 `backend/data/erp.db`（可用环境变量 `ERP_DATA_DIR` 重定向）。连接时统一设置 PRAGMA：`journal_mode=WAL`、`foreign_keys=ON`、`busy_timeout=5000`。无需独立数据库服务，备份=拷文件。
- **认证**：JWT（HS256，有效期 1440 分钟），密码 bcrypt 哈希（passlib）。

### 1.2 后端分层

```
backend/app/
├── main.py          # create_app 工厂：CORS、/api 强制 no-cache 中间件、路由挂载、
│                    # lifespan（建表 + 种子数据 + 每日汇率任务 + 每日预警扫描任务）
├── config.py        # Settings（.env 可覆盖）：端口无关、JWT、默认管理员、DATA_DIR
├── database.py      # engine / SessionLocal（autoflush=False）/ get_db / init_db
├── models/          # SQLAlchemy 模型，按域拆文件（auth/foundation/sales/purchase/
│                    # production/inventory/tax_refund/system_config）
├── schemas/         # Pydantic 请求/响应模型，与 models 一一对应拆分
├── routers/         # API 路由层（业务逻辑主要在这一层）
├── services/        # reminder.py（预警）、exchange_rate_fetcher.py（汇率）
└── utils/           # auth.py（JWT/RBAC 依赖）、batch_no.py（单据号）、
                     # crypto.py（Fernet）、ai_chat.py（AI Agent）
```

## 四、API 设计规范

- **风格**：RESTful + 动作后缀。资源用名词复数（`/api/sales/orders`），状态变更用动词子路径：`POST /orders/{id}/approve`、`/unapprove`、`/receipts/{id}/red`（红冲）、`/declarations/{id}/submit`、`/payments/{id}/review`。
- **统一响应**：列表返回 `{total, page, page_size, items: [...]}`；写操作返回 `{id?, xxx_no, message}`；业务错误以 HTTP 400/404/409 + `{"detail": "中文提示"}` 返回，detail 面向用户可直接展示。
- **分页**：`page`（≥1）+ `page_size`（多数上限 100，采购订单 200）；筛选参数平铺在 query string。
- **命名**：后端字段 snake_case，前端 camelCase，由 `request.js` 拦截器双向转换。
- **单据编号**：统一由 `utils/batch_no.py` 生成——短格式 `前缀-YYMMDDNN`（如 `SO-26083101`），批次号 `YYYYMMDD-NNN`（可带前缀 RA-/FG-）。采用 MAX+1 + flush + 生成后查重递增，避免并发撞号与删号复用。前缀对照：SO 销售订单、QT 报价、SD 发货、PO 采购订单、PR 采购需求(已停造)/采购入库单、MO 生产（已下线，历史保留）、WO 委外、MU 手动原料出库、RE 待入库收货(RE-YYMMDDNN)、ST 库存流水、STK 盘点、AR 应收、AP 应付、CR 收款、PM 付款、TS 退税申报（MI 发料/FG 完工入库/PI 加工费发票随生产管理下线停用）。

### 权限模型（RBAC + 授权域）

- 权限码即菜单码（`menu:sales:orders` 等），启动时由 `_seed_rbac` 幂等播种；7 个内置角色（admin/sales_manager/purchase_manager/production_manager/finance_manager/warehouse_keeper/readonly）。
- `User.has_permission`：admin 角色恒真；`get_current_admin` 仅 admin 角色可通过。
- 写端点用 `require_permission(code)`；读端点用 `require_any_permission(*域)`（本域 + 业务引用域，例如销售订单读域含发票/发货/收款/转采购/转委外域；显式禁止把 `menu:inventory*`、`menu:production:batch`、`menu:dashboard` 当引用域，防库管员/只读漏入）。已弃用权限码：`menu:hs-codes`、`menu:sales:customs`、`menu:tax`（报关/退税界面未发布，启动时自动清理其角色关联）。

## 五、认证与安全

- 登录 `POST /api/auth/login` → `{access_token, user}`；前端存 localStorage，axios 带 `Authorization: Bearer`，401 自动跳登录。
- JWT payload 仅 `{"sub": "<user_id>", "exp"}`，HS256，密钥/时长可在 `.env` 覆盖（默认 1440 分钟）。
- 密码 bcrypt；`python-jose` 签发/校验。
- 敏感配置（企微 Secret、AI API Key）Fernet 对称加密入库：密钥文件 `backend/app/.encryption_key` 首次自动生成；接口返回脱敏（`gAAA****xxxx`）；更新接口有「空值/脱敏/原密文回传不二次加密」守卫。
- 全部 `/api/*` 响应强制 `Cache-Control: no-cache`。

## 七、部署方案

### 开发模式

```bash
python launcher.py            # 安装依赖（backend/venv + npm install）并启动前后端
# 或 python launcher.py start / install
# 后端 http://localhost:8788（ERP_DEV=1 时热重载），前端 http://localhost:5173
# 默认账户 admin / admin123
```

### 生产模式

1. `cd frontend && npm run build` → 产物部署到 `backend/frontend_dist`；
2. 不设 `ERP_DEV` 环境变量启动后端：`python backend/run.py`（0.0.0.0:8788），后端直接托管前端静态文件并对未知路径回退 index.html（SPA）；
3. 数据目录：`backend/data/`（`ERP_DATA_DIR` 可重定向）；备份即备份 `erp.db`（WAL 模式，注意连同 -wal/-shm 或停服备份）。

### 常用运维命令（launcher.py）

| 命令 | 作用 |
|------|------|
| `python launcher.py` | 安装 + 启动 |
| `python launcher.py start` / `install` | 仅启动 / 仅安装 |
| `python launcher.py reset-db` | 删除数据库文件（清空全部数据） |
| `python launcher.py init-db` | 重置库 + 启动后端 + 跑 `scripts/init_all.py` 录入纺织全流程演示数据 |
